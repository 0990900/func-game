# FP Draft Game

함수형 프로그래밍의 타입클래스를 설명보다 먼저 플레이로 익히는 4인용 드래프트 카드게임입니다. 덱은 81장입니다.

## 실행

```bash
npm install
npm run build
npm start
```

브라우저에서 `http://localhost:2567`을 엽니다. 서버가 `0.0.0.0`에 붙으므로 다른 기기에서는 이 머신의 LAN
주소나 Tailscale 주소에 같은 포트로 접속할 수 있습니다. 포트를 바꾸려면 `COLYSEUS_PORT=4000 npm start`.

화면을 고칠 때는 Vite를 따로 띄우는 편이 낫습니다. 저장하면 바로 반영됩니다.

```bash
npm start                            # 게임 서버, 2567
cd client && npm run dev -- --host   # 화면, 저장하면 즉시 반영
```

## 한 판의 흐름

네 명이 함께 하고, 사람이 모자라면 빈자리를 Bot이 채웁니다. 시작할 때 비밀 목표를 두 장 중 하나 고릅니다.

손패는 없습니다. **차례가 되면 덱에서 한 장이 뽑히고, 그 한 장을 어떻게 쓸지만 정합니다** — 내 플레이
영역에 놓거나, 중앙 시장의 카드 한 장과 바꿔 옵니다. 어느 쪽이든 한 턴을 씁니다. 각자 15장을 놓으면
게임이 끝납니다.

## 카드

컨테이너 카드는 `Maybe.map`처럼 **타입과 연산**이 짝지어져 있습니다. **어떤 연산을 가지는지는 타입마다
다릅니다** — 그 자체가 이 게임의 내용입니다.

| | map ap pure chain | chainRec | alt | zero | filter | reduce | traverse | bimap |
|---|:---:|:---:|:---:|:---:|:---:|:---:|:---:|:---:|
| Maybe | ○ | ○ | ○ | ○ | ○ | ○ | ○ | ✗ |
| Either | ○ | ○ | ○ | **✗** | **✗** | ○ | ○ | ○ |
| List | ○ | ○ | ○ | ○ | ○ | ○ | ○ | ✗ |
| Task | ○ | ○ | ○ | **✗** | **✗** | **✗** | **✗** | **✗** |

- Task는 값을 내주지 않으므로 접을 수도, 뒤집을 수도, 거를 수도 없습니다
- Either는 실패할 때 반드시 이유를 들고 있으므로 빈 값(`zero`)을 만들 수 없습니다
- 칸이 둘인 것은 Either뿐이라 `bimap`도 Either에만 있습니다

**조커**는 한 장이 **연산 하나**를 맡습니다. 컨테이너 칸이 비어 있는 `*.map`과 `*.*`는 그 연산이 네
컨테이너에 동시에 들어가고(`*.map` 한 장이 Functor 4개), 컨테이너가 적힌 `Maybe.*`는 거기에만 들어갑니다.
어떤 연산이 될지는 게임이 점수가 가장 높아지는 쪽으로 정합니다. 조커만으로 이룬 조합은 점수는 받지만
Claim할 수 없습니다.

**유틸리티 카드** 12종은 조합에 쓰이지 않고 몇 장을 모았는지로만 점수가 됩니다. k번째 카드가 k+1점이라
모을수록 커집니다.

## 점수

**조합** — 사다리는 일직선이 아닙니다. `Applicative`와 `Chain`은 `Apply`에서 갈라진 형제이고 `Monad`는
둘이 만나는 지점입니다. `Alt` → `Plus` 가 두 번째 갈래이고 `Alternative`가 그 합류점입니다. 점수는 필요한
카드 수 하나로만 정합니다 — 1장 2점, 2장 4점, 3장 6점, 4장 9점, 5장 11점.

**같은 연산** — `map`을 Maybe와 List 양쪽에서 가지면 2점, 세 곳이면 5점, 네 곳이면 9점입니다. 하나의
인터페이스를 여러 타입에 구현하는 것이 타입클래스이고, 그 축에 점수가 붙습니다. 조커는 세지 않습니다.

**Claim** — 조합을 새로 완성하면 자동으로 선언됩니다. 같은 조합은 게임 전체에서 한 사람만 가져갑니다.
한 장으로 여러 개를 동시에 완성하면 n번째가 n점이라, 몰아서 완성할수록 유리합니다.

**비밀 목표** — 게임이 끝날 때 공개되고 6~7점이 붙습니다.

## 설계

규칙은 `src/core`에 두고 네트워크·화면과 분리합니다. 서버가 authoritative state를 소유하며, 클라이언트에는
각 플레이어가 볼 수 있는 상태만 투영해서 보냅니다. 비밀 목표는 그 경계에서 지워지므로 애초에 전송되지
않습니다.

규칙 코어는 TypeScript와 [Effect](https://effect.website)로 작성했습니다. 명령 실행과 규칙 위반을 `Effect`와
`Data.TaggedError`로 다루고, 방마다 `Semaphore(1)`로 명령을 한 줄로 세웁니다 — Colyseus는 async 핸들러의
await 사이를 직렬화해주지 않기 때문입니다. 셔플·id·시계는 주입 가능한 서비스로 분리해 테스트가 결정적으로
돌아가게 했습니다.

화면은 React와 PixiJS입니다. 카드 테이블은 캔버스, 나머지는 DOM이고 상태는 zustand 한 곳에 있습니다.
캔버스 렌더링이나 연결 수명주기처럼 부수효과가 핵심인 경계는 명시적인 코드로 유지합니다.

봇의 턴은 서버가 450~850ms 뒤에 예약하고, 실행 직전에 여전히 그 봇의 턴인지 확인한 다음 명령을 보냅니다.
기다리는 동안 다른 방의 진행을 막지 않습니다.
